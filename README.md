# Open Behavioral Data Toolkit

A reproducible Python toolkit for behavioral research: data validation, questionnaire
scoring, descriptive statistics, correlation analysis and reporting.

> **Status: v0.1.0, alpha.** The API may change between 0.x releases. The toolkit has a
> test suite (see [docs/QA_REPORT.md](docs/QA_REPORT.md) for what was actually run), but it
> has not been used or reviewed by external researchers yet. Treat results as you would any
> new research software: verify them against a tool you trust before relying on them.
>
> **Not a clinical tool.** The toolkit performs descriptive statistics and arithmetic on
> questionnaire data. It provides no diagnoses, cut-offs, norms or clinical conclusions,
> and its output must not be used as a basis for them.

## Why this exists

Behavioral studies routinely need the same small steps: check the data, score the scales,
estimate reliability, look at correlations, and leave a record of what was done. This
package provides those steps as plain, documented functions with **explicit missing-data
handling**, input validation that fails loudly, and tests checked against independent
reference calculations. It is a workflow layer, not a replacement for `scipy.stats`,
`statsmodels` or `pingouin`.

## Installation

The package is not published on PyPI yet. Install from a clone of this repository
(Python 3.11 or newer):

```bash
git clone https://github.com/meworo/open-behavioral-data-toolkit.git
cd open-behavioral-data-toolkit
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"      # development install (tests, linting, plotting)
# or: pip install .          # runtime only (pandas, NumPy, SciPy)
# or: pip install ".[plot]"  # runtime + Matplotlib helpers
```

## Quick start

Run from the repository root. The data file is **synthetic** (generated by
`examples/generate_synthetic_data.py`); no real participants are involved.

```python
import behavioral_data_toolkit as bdt

df = bdt.load_csv("examples/data/synthetic_survey.csv")

# 1. Check quality (findings only; nothing is changed)
items = [f"sw{i}" for i in range(1, 7)]
rules = {c: bdt.ValueRule(minimum=1, maximum=5) for c in items}
quality = bdt.data_quality_summary(df, duplicate_subset=["participant_id"], rules=rules)
print(quality.n_duplicate_rows, quality.n_invalid_values)

# 2. Clean explicitly (these are your decisions, made visible in code)
clean = df.drop_duplicates(subset="participant_id").copy()
clean[items] = clean[items].astype(float)
for row in quality.invalid.itertuples():
    clean.loc[row.row, row.column] = float("nan")

# 3. Score a scale (items sw2 and sw5 are reverse-keyed in this synthetic data)
scale = bdt.ScaleDefinition("synthetic_wellbeing", tuple(items), 1, 5, reverse_items=("sw2", "sw5"))
scores = bdt.score_questionnaire(clean, scale)

# 4. Internal consistency (reverse-score first) and a correlation
reversed_items = bdt.reverse_score(clean, 1, 5, columns=["sw2", "sw5"])
alpha = bdt.cronbach_alpha(reversed_items, items)
print(f"alpha={alpha.alpha:.2f} (n={alpha.n_observations}, excluded={alpha.n_excluded})")
print(bdt.pearson(clean["age"], scores))
```

A complete workflow that also writes a JSON/Markdown report with reproducibility metadata is in
[`examples/example_workflow.py`](examples/example_workflow.py); its output is in
[`examples/output/`](examples/output/). A step-by-step guide is in [docs/USAGE.md](docs/USAGE.md).

## What is included (v0.1.0)

| Module | Provides |
|---|---|
| `loader` | `load_csv`, `inspect_dataframe`, `validate_columns` |
| `validator` | `missing_summary`, `find_duplicates`, `find_invalid_values`, `data_quality_summary` |
| `scoring` | `reverse_score`, `composite_score`, `ScaleDefinition`, `score_questionnaire(s)` |
| `stats` | `mean`, `median`, `std`, `distribution_summary`, `cronbach_alpha` |
| `correlation` | `pearson` (with Fisher-z CI), `spearman`, `correlation_matrix` |
| `reporting` | `AnalysisReport` (JSON/Markdown export), data fingerprint, environment metadata |
| `plotting` (optional) | `plot_distribution`, `plot_correlation_heatmap` |

## Scientific notes

Every statistical function documents its mathematical basis, assumptions and limitations in
its docstring and in [docs/STATISTICAL_METHODS.md](docs/STATISTICAL_METHODS.md). Two points
worth stating up front:

- **Cronbach's alpha is not proof of unidimensionality or construct validity.** It summarises
  inter-item covariance in a particular sample and rises with the number of items.
- **p-values are unadjusted.** No multiple-comparison correction is applied in v0.1.0.

Known limitations are listed in [docs/KNOWN_LIMITATIONS.md](docs/KNOWN_LIMITATIONS.md).
